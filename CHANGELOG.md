### Added
- **Widget tests for Batch page, AI tools grid and export sheet**: 14 new tests (widget suite 55 -> 69). Batch: empty state, preset choice reveals intensity, copied-edits switch unlocks when the clipboard holds edits, size/format tracking, auto enhance. AI tools grid: tap vs disabled cards, sheet pops before the action runs, missing-model card shows the download size, installed model shows no ring. Export sheet: share vs save results, PNG/TIFF hide the quality slider, EXIF switch disabled off JPEG, initial options seed the sheet, a social size forces JPEG with its preset quality.
- **Widget tests for Models page and video crop sheet**: 8 new tests. The crop sheet now opens via `showVideoCropSheet` with swipe-to-dismiss off, so dragging a crop handle cannot be taken over by the sheet drag (not verified on a device).
- **Lip colour and brow enhance (Wave 2 W4-M1)**: two new face tools built from the existing 478-point landmark masks, so no new model weights. Lips are the lip ring minus the mouth opening (teeth untouched); brows are the brow rings. Both are editable local adjustments, available as tool cards and as Smart commands in Arabic and English ("lip colour", "red lips", "enhance brows", "احمر الشفاه", "حسن الحواجب"). Full 19-class face parsing is deferred: the common weights are trained on CelebAMask-HQ (non-commercial research licence).
- **Low-light rescue (Wave 2 W5-M1)**: model-free denoise plus exposure lift in pure Dart: shadow-weighted luma denoise, edge-guarded chroma-noise suppression, and a Zero-DCE-style exposure curve with bounded chroma follow (no colour cast). One undo step, runs in an isolate, no download. Smart commands in Arabic and English ("fix this dark photo", "denoise", "حسّن الصورة الليلية", "قلل الضجيج"). Intent benchmark: 1,185 commands, 100 % AR and EN.
- **Manual low-light panel (W5)**: an AI-tools card opens a sheet with Lift and denoise, Preserve detail and Colour noise sliders (AR/EN), applied as one undo step through the existing model-free path. Needs an on-device check of the slider feel and speed.
- **Dark-photo hint (W5)**: when the analysis gives a photo the Brighten suggestion (mean luma below 0.3), the Smart panel also shows a Low-light rescue chip that opens the same sliders. Derived from the existing suggestions, so no extra analysis pass.
- **Settings fix + tests**: a settings change made before the first preferences load finished (for example a language switch right at launch) was silently not saved; the preferences future is now shared so it persists. Added unit tests for defaults, the existing-install onboarding rule, index clamping and a persist/restart round trip. Setters now also wait for the first load, so the load can no longer overwrite a change made while it was running. First-run tips have widget tests (next, skip, finish, Arabic).
- **Local inference telemetry (Wave 2 W1)**: every model run records model, engine format, latency and memory in a bounded in-memory log; the per-model summary is appended to Settings › Error log for the user to copy or share. Nothing is uploaded or stored on disk.
- **Timeline captions (Wave 2 W3-M6b)**: a Captions tool in the video editor: language chips (auto, Arabic, English), Whisper tiny download through the existing model dialog, progress and cancel (partial captions kept), editable cue list, SRT/VTT sharing, and burned-in export through the text overlay path (trim, speed and reverse honoured).
- **Whisper model mirror (`models-v1.5`)**: the three Whisper tiny files are mirrored as release assets of this repository (SHA-256 verified after upload, identical to upstream) and are now regular `ModelRegistry.all` entries, so they show in Settings > AI models and get the same URL-then-mirror download fallback as every other model.
- **Caption service (Wave 2 W3-M6a)**: `CaptionService` runs a whole captioning pass UI-free: decode the video's speech audio (`VideoEngine.decodeSpeechAudio`, mono 16 kHz, cached), open the model, run the cancellable `CaptionJob`, always release the model (also on failure or cancel), and write `.srt`/`.vtt` sidecars with safe file names. `openWhisperTiny` opens the installed Whisper files and reports a missing download as `AiException(notDownloaded)`. 12 new tests (progress, partial results on cancel/failure, no-audio, model always closed, sidecar round-trips, path-safe names). The timeline caption button comes next.
- **Whisper transcriber (Wave 2 W3-M5)**: `WhisperTranscriber` implements the `AutoTranscriber` seam end to end: silence skip, 16 kHz log-mel in an isolate, encoder, KV-cached merged decoder (`CachedWhisperDecoderStep`: full prompt first, then one token per step, cross-attention K/V reused, replaced tensors released), per-window language auto-detect (or a fixed language), timed segments. `OnnxWhisperRuntime` binds it to ONNX Runtime, keeping the encoder output and KV cache inside the runtime as handles. New `ModelRegistry.speech` specs (onnx-community/whisper-tiny, Apache-2.0, pinned to a Hugging Face commit with SHA-256, ~41 MB: uint8 encoder + int8 merged decoder + vocab). Checked outside the app with desktop ONNX Runtime: the Dart log-mel fed to these exact graphs transcribed a real English clip word for word. 13 new tests with fake graphs. Pending: on-device smoke test, project mirror (`models-v1.5`), UI entry point.
- **Whisper token layer + greedy decoder (Wave 2 W3-M4)**: `whisper_decoding.dart` holds everything around the neural net: multilingual special-token layout and language ids (Arabic = 50272), the decoder prompt, a byte-level BPE text decoder (split multibyte characters never throw), the reference timestamp rules (paired, never backwards, forced first timestamp, timestamp-vs-text probability), a bounded greedy loop over a pluggable `WhisperDecoderStep` with a repetition guard and token cap, and timestamped tokens to `CaptionSegment`s clamped to the window. 17 new tests with scripted decoders.
- **Whisper audio front end (Wave 2 W3-M3)**: `whisper_frontend.dart` turns PCM into the 80x3000 log-mel the Whisper encoder expects, in pure Dart: resample to 16 kHz, 30 s pad/trim, a mixed-radix FFT (n=400), Slaney mel filterbank, reflect-padded centred STFT and the reference normalisation. 13 new tests (FFT vs naive DFT, filterbank shape, tone lands in the right mel bin, degenerate inputs) - 588 green, `flutter analyze` clean.
- **Captioning job pipeline (Wave 2 W3-M2)**: `captioning.dart` turns the v1.4 FFmpeg PCM decode into a timeline-safe `SubtitleTrack` through a pluggable `AutoTranscriber` seam — the real Whisper transcriber will implement the same contract next with zero call-site changes. **30 s windows** slide over the audio (any sample rate; a sub-second tail folds into the previous window instead of a sliver), a sequential background **`CaptionJob`** reports per-window progress, is **cancellable between windows with partial results kept**, records transcriber failures as honest partial results, shifts segment times to absolute timeline times and assembles the track through the W3-M1 sanitisation (overlapping ASR segments are truncated, never duplicated). 12 new tests — **575 tests green, `flutter analyze` clean**.
- **Subtitle infrastructure for auto-captions (Wave 2 W3-M1 starts)**: the data layer under "Whisper AR/EN captions" ships first — `subtitles.dart` with `SubtitleCue`/`SubtitleTrack` (sorted cues, per-word timings for later karaoke styling, JSON round-trip for project files), **spec-correct SRT + WebVTT writers and strict bounded parsers** (comma vs dot clocks, hours ≥ 100 safe, NOTE/identifier blocks tolerated, ≤ 50k lines/cues and ≤ 5k chars per cue — malformed input raises `SubtitleFormatException`, never crashes or hangs; files truncated mid-write open with everything read so far, total garbage raises), **track sanitisation** (invalid cues dropped, overlaps truncated earlier-yields, times clamped to the video duration, captions cleaned + wrapped automatically) and the **dialect-tolerant Arabic pass** from the W3 scope (tatweel strip, opt-in alef folding for ASR-text comparison, punctuation spacing repair, word-boundary line wrapping where every line is hard-bounded ≤ max chars — never breaks inside a word). 22 new tests (model + JSON round-trips, SRT/VTT round-trips, fuzz gates incl. a >50k-cue bounded error and truncated-file tolerance, sanitisation policies, AR shaping) — **563 tests green, `flutter analyze` clean**. The tests caught three real bugs before ship: `replaceAll` does not interpolate `$1` backreferences (literal `$1` leaked into captions), the line wrapper never emptied its buffer on flush (a 633-char runaway line), and the cue cap truncated silently instead of raising.
- **Camera-neutral RAW colour + highlight recovery (Wave 2 W2 M2-4)**: DNG files no longer render with a colour cast. A new `colour_render.dart` implements the DNG-spec colour pipeline in pure Dart — white balance through `AsShotNeutral` (the shot's neutral maps to `[1,1,1]` in camera space), `ColorMatrix1` inverted and Y-normalised into a camera→XYZ matrix, **Bradford chromatic adaptation from the shot illuminant to D65**, then XYZ→linear-sRGB. Achromatic scene colours land exactly on the sRGB white (the camera's D65-white response renders 255/255/255 end-to-end in tests), and a **highlight-recovery shoulder** runs on the linear data between matrix and gamma: pixels above 0.95 take a quadratic, never-overshooting shoulder blended toward their Rec.709 luminance in proportion to clip depth, so blown channels lose their magenta/green fringes instead of hard-clipping; the clipped-pixel fraction is returned for diagnostics. This milestone also fixed a real parser bug that had made every negative `ColorMatrix` coefficient unreadable: SRATIONAL numerators were read unsigned (−0.7 came back as ~4e9). Files without colour metadata keep the legacy identity path bit-for-bit; singular matrices and degenerate neutrals degrade gracefully. 17 new tests (matrix round-trips, white→white, grey invariance, SRATIONAL sign through a byte-built DNG, end-to-end white/hue/identity renders, recovery bounds + luminance monotonicity) — **541 tests green, `flutter analyze` clean**.
- **RAW/DNG open path (Wave 2 W2 M2-1)**: real camera files now open in Lumora. An in-house pure-Dart pipeline — fuzz-safe TIFF/IFD parser (loop- and depth-bounded, bounds-checked, raises instead of crashing), a DNG document layer that classifies the CFA raw IFD vs embedded previews and reads pattern / black / white levels / ActiveArea, a strip decoder for uncompressed and Adobe-deflate raw (8/12/14/16-bit-in-16 storage), bilinear demosaic with CFA-pattern-aware diagonal/orthogonal interpolation, and sRGB-gamma 8-bit output handed to the normal editor pipeline. **Preview-first honesty**: raw payloads compressed with lossless JPEG (the phone-default) decode into the largest embedded preview instead, and the reason ("raw data uses lossless JPEG — decode lands in the next RAW milestone") is shown in Arabic and English; the photo picker accepts `.dng`/`.tif` beside everyday images. 17 new tests (parser fuzz gates, strip bounds, ActiveArea crop, deflate round-trip, uniform-sensor demosaic, preview fallback, honest failures) — **514 green**, `flutter analyze` clean. The tests caught two real bugs before they shipped: a missing ActiveArea tag (legal per the DNG spec) crashed the decoder with an impossible crop, and the preview fallback was unreachable because the document layer rejected unsupported compressions at parse time.
- **LiteRT/NPU runtime (Wave 2 "Pro Intelligence" W1 starts)**: a second inference engine beside ONNX Runtime. `LiteRtInferenceEngine` (via `tflite_flutter` 0.12.1, LiteRT) runs every `.tflite` model on the fastest accelerator the device offers — **NPU through Android NNAPI on an explicit SoC allow-list** (Snapdragon 8-series, Google Tensor, Dimensity 9000+; unknown SoCs never get the NPU because a native abort cannot be caught from Dart), then the **GPU delegate** (OpenGL on Android, Metal on iOS), then **CPU kernels**. A per-session blacklist never retries a delegate that failed once for a model, and `EngineSelector` picks LiteRT vs ONNX per model (LiteRT only when acceleration is on, the device offers a delegate, and the model ships a `.tflite` variant); any LiteRT failure transparently retries on ONNX, and two consecutive failures pin ONNX for the session. The interpreter lives in a **dedicated worker isolate** (raw byte-buffer tensor protocol), so no `invoke()` ever blocks the UI thread. Model specs gained `format` (`onnx`/`tflite`) and an optional `lite` sibling spec — the download/checksum/cache path works unchanged for both formats. CPU-only devices and acceleration-off keep today's behaviour bit-for-bit. 26 new tests (delegate policy + SoC parsing, wire protocol encode/decode, engine fallback & blacklist, selector pinning) — 491 green, `flutter analyze` clean.

- **First real LiteRT variant — scene classifier on LiteRT**: `ModelRegistry.mobilenetSceneLite` ships the official uint8 quantised MobileNetV2 (1.0, 224) from Google's `google-coral/test_data` (3,610,798 B, SHA-256 `7aad0c74…d4776`, Apache-2.0), registered as the `.lite` sibling of the ONNX scene model and mirrored on the `models-1.4` release (asset re-downloaded and verified byte-identical). The graph was parsed before registration: `input` uint8 `[1, 224, 224, 3]` NHWC → `MobilenetV2/Predictions/Softmax` uint8 `[1, 1001]` (scale 1/256, zero point 0). `SceneClassifierPipeline` now picks its contract from `InferenceEngine.specFor` — float NCHW + ImageNet mean/std for the ONNX sibling, uint8 NHWC 0..255 for LiteRT — dequantises through the wire's scale/zero point, maps probabilities through ln() so the existing softmax aggregation recovers the exact distribution, and drops class 0 (background). LiteRT variants are **never downloaded on demand** (optional-model policy): `EngineSelector` runs a variant only when its file is already installed, and installing a model from Settings now fetches its LiteRT sibling in the same tap. TensorWire carries quantisation parameters; a real end-to-end integration test (`test/integration/`, env-gated) loads the actual graph through the worker isolate on hosts with the LiteRT C library provisioned.
- **16-bit TIFF export (Wave 2 W2 M2-3)**: the export sheet gains a "TIF" format backed by a spec-correct pure-Dart 16-bit RGB TIFF writer — little-endian classic IFD with the TIFF inline-value rule honoured, uncompressed uint16 strips capped at ~1 MB, channel lift v·257 (0x00→0, 0xFF→65535 exactly, alpha dropped), Software tag set, resolution unit inch. This is Lumora's first export path that carries more than 8 bits per channel — the receiving end of the W2 pipeline story (decode → edit → **export**). 3 new tests round-trip the written file through the project's own TIFF parser (tag assertions, exact 16-bit values, multi-strip readability) — **524 tests green, `flutter analyze` clean**.
- **Lossless-JPEG (SOF3) DNG decode (Wave 2 W2 M2-2)**: the phone-default raw compression now decodes on-device. A pure-Dart ITU-T T.81 lossless decoder — marker walk (SOI/SOF3/DHT/DRI/SOS), canonical Huffman tables, category-16 escape, MSB-first bit reader with FF-00 stuffing, the full 7-prediction lattice, per-component point transform Pt, restart intervals with predictor reset — runs per DNG strip with width/height/precision validation and an MCU budget that turns corrupt entropy streams into bounded format errors, never crashes or hangs. Phone DNGs (raw CFA stored as lossless JPEG) now open with their **real sensor data** — demosaic, black/white levels and ActiveArea all apply — instead of the embedded preview; broken payloads keep the honest preview fallback. 7 new tests including a fixture-side SOF3 encoder (predictor 1/5 round-trips, 8-bit precision, DRI+RSTn, multi-strip DNGs, truncation fuzz gate) — **521 tests green, `flutter analyze` clean**.
- **Model mirrors restored (bug fix)**: the `models-v1.3` tag had **no release** — every v1.3 mirror URL returned 404. Release recreated with all ten assets, each downloaded from its pinned URL, SHA-256-verified against the registry and uploaded byte-identical (incl. the 208 MB LaMa fp32). The v1.4 mirror tag/name mismatch was fixed the same way (`models-1.4`, short asset names; yunet/facemesh re-verified byte-identical).

### العربية
- **خط عمل التسميات (الموجة الثانية مس 3، م3-2)**: `captioning.dart` يحوّل فك FFmpeg من 1.4 إلى `SubtitleTrack` آمنة على الطريقة الزمنية عبر واجهة `AutoTranscriber` قابلة للتعويض — مفكّك Whisper الحقيقي ينفذ العقد نفسه تاليًا دون تغيير أي مستدعٍ. **نوافذ 30 ثانية** تنزلق فوق الصوت (أي معدل عينات؛ الذيل الأقصر من الثانية يُطوى في النافذة السابقة بدل نافذة شظية)، و**`CaptionJob`** خلفي متسلسل يبلّغ التقدم لكل نافذة و**قابل للإلغاء بين النوافذ مع حفظ النتائج الجزئية**، ويسجل فشل المفكك كنتيجة جزئية صادقة، وينقل الأزمنة إلى المطلق ويجمّع المسار عبر تطهير م3-1 (مقاطع ASR المتداخلة تُقتطع ولا تُكرر). 12 اختبارًا جديدًا — **575 اختبارًا أخضر وتحليل نظيف**.
- **بنية التسميات التحتية للتسميات التوضيحية (بداية الموجة الثانية مس 3، م3-1)**: طبقة البيانات تحت «تسميات Whisper عربي/إنجليزي» تُشحن أولًا — `subtitles.dart` بـ `SubtitleCue`/`SubtitleTrack` (تسميات مرتبة، توقيتات لكل كلمة للأنماط الكاريوكية لاحقًا، دورة JSON لملفات المشروع)، **كتّاب SRT + WebVTT صحيحا المواصفات ومحللان صارمان محدودا الحدود** (فاصلة مقابل نقطة، ساعات ≥ 100 آمنة، كتل NOTE/المعرفات متسامَحة، ≤ 50 ألف سطر/تسمية و≤ 5 آلاف حرف لكل تسمية — المدخل المعطوب يرمي `SubtitleFormatException` بلا انهيار أو تعليق؛ الملفات المقطوعة أثناء الكتابة تُفتح بما قُرئ، والرماد الخالص يرمي)، **تطهير المسار** (التسميات الفاسدة تُسقط، التداخلات تُقتطع السابق يتنازل، الأزمنة تُثبت على مدة الفيديو، التنظيف والالتفاف تلقائيان) و**المرحلة العربية المتسامحة مع اللهجات** من نطاق مس 3 (إزالة التطويل، طي الألف اختياري لمقارنة نصوص التعرف، إصلاح تباعد الترقيم، التفاف أسطر عند حدود الكلمات مع حد صارم لطول كل سطر — لا كسر داخل الكلمة أبدًا). 22 اختبارًا جديدًا (النموذج ودورات JSON، دورات SRT/VTT، بوابات عشوائية بينها خطأ محدود لـ >50 ألف تسمية وتسامح الملف المقطوع، سياسات التطهير، التشكيل العربي) — **563 اختبارًا أخضر وتحليل نظيف**. الاختبارات أوقفت ثلاثة أخطاء حقيقية قبل الإرسال: `replaceAll` لا يفسّر الإحالات `$1` (تسرب حرفي `$1` إلى التسميات)، والملفّ لم يُفرّغ مخزنه عند التفريغ (سطر هارب بطول 633)، وسقف التسميات كان يقطع بصمت بدل الرمي.
- **التلوين المحايد للـ RAW واستعادة الإبراقات (الموجة الثانية مس 2، م2-4)**: ملفات DNG لم تعد تُرسم بصفة لونية. وحدة جديدة `colour_render.dart` تنفذ خط ألوان مواصفات DNG بلغة Dart نقية — توازن أبيض عبر `AsShotNeutral` (يصبح محايد اللقطة `[1,1,1]` في فضاء الكاميرا)، وقلب `ColorMatrix1` وتطبيعه على Y إلى مصفوفة كاميرا→XYZ، و**تكييف برادفورد اللوني من إضاءة اللقطة إلى D65**، ثم XYZ→sRGB الخطي. ألوان المشهد المحايدة تستقر تمامًا على أبيض sRGB (استجابة الكاميرا لأبيض D65 تُرسم 255/255/255 من الطرف للطرف في الاختبارات)، و**كتف استعادة الإبراقات** يعمل على البيانات الخطية بين المصفوفة وغاما: البكسلات فوق 0.95 تأخذ كتفًا تربيعيًا لا يتجاوز الحد أبدًا، ممزوجًا نحو إضاءتها Rec.709 بنسبة عمق القص، فتفقد القنوات المحترقة هوامشها البنفسجية/الخضراء بدل القص القاسي؛ ونسبة البكسلات المقصوصة تُعاد للتشخيص. هذا المعلم أصلح أيضًا خللًا حقيقيًا في المحلل جعل كل معامل `ColorMatrix` سالبًا غير قابل للقراءة: كانت بسط SRATIONAL يقرأ كعدد غير مُوقّع (‑0.7 كان يعود بحجم ~4e9). الملفات بلا بيانات لونية تحتفظ بالمسار القديم بت بت، والمصفوفات المفردة والمحايدات الفاسدة تتدهور بلطف. 17 اختبارًا جديدًا (دورات المصفوفة، أبيض→أبيض، ثبات الرمادي، إشارة SRATIONAL عبر DNG مبني بالبايت، رسومات نهائية للأبيض/الصبغة/الهوية، حدود الاستعادة ورتيّتها) — **541 اختبارًا أخضر وتحليل نظيف**.
- **تصدير TIFF ذي 16-بت (الموجة الثانية مس 2، م2-3)**: ورقة التصدير تكتسب صيغة «TIF» خلفها كاتب TIFF بحجم 16-بت صحيح المواصفات بلغة Dart نقية — IFD كلاسيكي صغير النهاية مع التزام قاعدة القيم المضمنة، شرائط uint16 غير مضغوطة محدودة ب~1 ميجابايت، رفع القنوات v·257 (0x00→0 و0xFF→65535 بدقة، مع إسقاط ألفا)، وسم Software، ووحدة الدقة بالبوصة. هذا أول مسار تصدير في لومورا يحمل أكثر من 8 بت لكل قناة — الطرف المستقبِل لقصة خط W2 (فك ← تحرير ← **تصدير**). 3 اختبارات جديدة تمرر الملف المكتوب عبر محلل TIFF الخاص بالمشروع (تأكيدات الوسوم، قيم 16-بت دقيقة، قراءة شرائح متعددة) — **524 اختبارًا أخضر وتحليل نظيف**.
- **فك JPEG بلا فقد (SOF3) في ملفات DNG (الموجة الثانية مس 2، م2-2)**: ضغط RAW الافتراضي في الهواتف يُفك الآن على الجهاز. مفك T.81 بلغة Dart نقية — جولة على العلامات (SOI/SOF3/DHT/DRI/SOS)، جداول Huffman القانونية، فئة الهروب 16، قارئ بت MSB مع حشو FF-00، شبكة التنبؤ الكاملة بسبعة متنبئات، نقطة التحويل Pt لكل مركّبة، فواصل إعادة التشغيل مع تصفير المتنبئات — يعمل لكل شريط DNG مع تحقق العرض/الارتفاع/الدقة وميزانية MCU تحوّل تدفقات الإنتروبيا المعطوبة إلى أخطاء محدودة بدل الانهيار أو التعليق. ملفات DNG من الهواتف تُفتح الآن **ببيانات مستشعرها الحقيقية** بدل الاكتفاء بالمعاينة المضمّنة؛ والبيانات المعطوبة تحتفظ بالاحتياط الصادق للمعاينة. 7 اختبارات جديدة بينها مُشفّر SOF3 في جانب الاختبار (دورات المتنبئ 1/5، دقة 8-بت، فواصل DRI+RSTn، ملفات متعددة الشرائح، بوابة اقتطاع) — **521 اختبارًا أخضر وتحليل نظيف**.
- **مسار فتح RAW/DNG (الموجة الثانية مس 2، م2-1)**: ملفات الكاميرات الحقيقية تُفتح الآن في لومورا. خط داخلي بلغة Dart نقية — محلل TIFF/IFD آمن ضد التلف (محدود العمق والحلقات، فحوص حدود، يرمي استثناء بدل الانهيار)، طبقة مستند DNG تفرّق شرائح CFA الخام عن المعاينات المضمّنة وتقرأ النمط ومستويات الأبيض والأسود وActiveArea، مفك شرائط للضغط غير المضغوط وAdobe-deflate (تخزين 8/12/14/16-بت داخل 16-بت)، demosaic خطي ثنائي يراعي هندسة نمط CFA، ومخرجات sRGB ذات 8-بت تُسلَّم لخط المحرر المعتاد. **الصدق أولًا بالمعاينة**: بيانات RAW المضغوطة بـ JPEG بلا فقد (الافتراضي في الهواتف) تُفك من أكبر معاينة مضمّنة بدلًا منها، ويظهر السبب («بيانات RAW تستخدم JPEG بلا فقد — الفك الكامل يصل في معلم RAW القادم») بالعربية والإنجليزية؛ ومنتقي الصور يقبل `.dng`/`.tif` بجانب الصور المعتادة. 17 اختبارًا جديدًا — **514 اختبارًا أخضر** وتحليل نظيف. الاختبارات أوقفت خللين حقيقيين قبل الإرسال: غياب وسم ActiveArea (مشروعي وفق مواصفات DNG) كان يُسقط المفك بقص مستحيل، ومسار احتياط المعاينة كان مستعصيًا لأن طبقة المستند ترفض الضغط غير المدعوم وقت التحليل.

## [1.1.1] - 2026-11-21

### Fixed
- **AI tools no longer close the app on Android.** Release builds are shrunk by R8, which renamed/removed ONNX Runtime's Java classes (`ai.onnxruntime.*`) that its native library looks up by name; the first AI tool then aborted the whole process ("Lumora Studio has stopped"). `android/app/proguard-rules.pro` now keeps ONNX Runtime, the flutter_onnxruntime bridge and FFmpegKit, and is wired into the release build type.
- Safer on-device inference: CPU execution by default (XNNPACK and KleidiAI kernels are now an opt-in "AI acceleration" switch in Settings), at most 4 threads, only one model loaded at a time, serialized runs, outputs released before inputs.
- Lower peak memory: the object eraser works on a copy capped at 4096 px (its mask too), and 4× upscale caps the input at ≈0.8 MP and no longer copies its ~200 MB buffers into a second isolate.
- Every AI tool checks that its model is on the device first: it asks before downloading and shows a progress dialog with retry. Failures are shown in plain words (no internet, damaged model, not enough memory, model cannot load on this device) instead of raw exceptions.

### Added
- **Settings › Error log**: a local log of Dart errors, breadcrumbs of each AI step, and — on Android 11+ — why the previous run ended (native crash, ANR, low memory) plus any uncaught JVM exception. Copy or share it; nothing is uploaded.
