# Architecture

```
      domain/      ModelRegistry (URLs, SHA-256, sizes, licenses, I/O contract)
      data/        ModelManager (download, verify, cache), InferenceEngine (ONNX)
      pipelines/   tensor utils + segmentation, matting, inpainting, upscale
      presentation/ model manager screen
    projects/      Drift database + repository (save/restore/rename/duplicate)
    settings/      persisted preferences
    home/          start screen: quick tools, projects
    onboarding/    first-run tips
    scanner/       document detection, perspective, scan filters, PDF writer
    collage/       layouts, cover-fit math, painter

assets/luts/       bundled .cube LUTs (generated by tool/generate_luts.py)
```

## State and edit history

* `EditState` (photo) and `VideoProject` (video) are immutable `freezed` values that serialize to JSON, so a project is just `(source path, JSON recipe)`.
* `EditHistory<T>` is an immutable undo/redo stack. Slider drags call `replace` (live updates, no history entry). `commit()` at the end of the gesture turns the whole drag into one undo step.
* AI operations that create new pixels (background removal, eraser, upscale) write a new PNG and set `EditState.rasterPath`. Undo just restores the previous path, so even "destructive" AI steps stay non-destructive. The original file is never modified.

## Photo render pipeline (GPU)

`PhotoRenderer.render(source, state)` chains fragment-shader passes. Each pass is `PictureRecorder` → `drawRect(Paint..shader)` → `Picture.toImageSync`:

1. **warp.frag**: crop, 90° turns, straighten (with auto-zoom), flips and perspective, in a single inverse-homography lookup. The matrix is built on the CPU by `buildInverseWarp` (unit tested).
2. **develop.frag**: white balance and exposure in linear light, levels (whites/blacks), luminance-masked highlights/shadows, S-curve contrast, 8-band HSL, vibrance/saturation, split toning, RGB + per-channel curves (256×1 texture), fade, and a 3D LUT (atlas `N²×N`, two bilinear taps blended across the blue slices, giving trilinear interpolation).
3. **Local adjustments**: for each mask, `develop` (+ `detail`, + `blur`) with the mask's own settings, then **mask_blend.frag** composites it through a brush texture, a linear or radial gradient, or the AI subject matte.
4. **detail.frag**: luma unsharp mask (sharpen), structure (small radius), clarity (large radius, mid-tone weighted) and dehaze (dark-channel prior).
5. **blur.frag**: separable gaussian, iterated for large radii.
6. **effects.frag**: chromatic aberration, glitch, duotone, vignette and grain. It is tile aware through `uTile`, so position-based effects line up seamlessly across export tiles.
7. **Overlays**: text, stickers and drawings painted with Flutter's canvas (`OverlayPainter`). The same code serves preview and export, so they are WYSIWYG.

### Texture orientation on OpenGL ES

On the Impeller GLES backend, images produced by `toImageSync` (render targets) are stored y-flipped. Convention used here:
* `warp.frag` is always the first pass and samples a *decoded* image, so it never flips.
* Every later pass samples render targets and flips `uv.y` under `#ifdef IMPELLER_TARGET_OPENGLES`.
* Data textures (curve LUT, 3D LUT atlas) are uploaded with `decodeImageFromPixels`, so they are never flipped.
* Brush and subject masks are always rasterised (or warped) into render targets first, so they follow the render-target rule.

### Preview proxies, isolates and tiling

* The editor decodes a **≤ 2048 px proxy** (`ImageDescriptor.instantiateCodec(targetWidth…)`) for real-time editing. Renders are coalesced, so only the newest state renders after a burst of slider events.
* **Export**: images up to 8192 px are rendered in a single GPU pass at full resolution. Larger images are decoded with `package:image` on a background isolate, split into 2048 px tiles with 64 px padding (`planTiles`), warped on the CPU (`warpTileCpu` in `compute`), coloured on the GPU with tile-aware uniforms, cropped and stitched (`blitTile`). Encoding (JPEG/PNG) runs in `Isolate.run`. WebP and HEIC use the platform encoders through `flutter_image_compress`.
* AI pre/post-processing (resize, normalisation, NCHW packing, matte upsampling, dilation, compositing) runs in isolates.

## Video

* **Preview**: `video_player` plays the clip under the playhead and moves to the next clip at the out-point. The look is previewed in real time with `ImageFilter.shader(video_filter.frag)` applied to the video texture (Impeller only). Text overlays are previewed as widgets.
* **Export**: `FfmpegCommandBuilder` produces an argument list (no shell quoting) with a `filter_complex` graph that:
  * per clip: `trim`/`atrim`, `reverse`/`areverse`, `setpts`/`atempo` chains, `crop`, `transpose`, then `scale`+`pad` to the output aspect, `fps`, `format=yuv420p`
  * joins clips with `concat` or `xfade` + `acrossfade` (offsets account for earlier overlaps)
  * applies the look (fast mode), overlays Flutter-rendered text PNGs with `enable='between(t,a,b)'`, and mixes music (`atrim`, `afade`, `amix`)
* **Studio mode** renders the cut without the look, extracts frames, runs each frame through `PhotoRenderer` (identical to the photo editor) and re-encodes with the original audio.

### Why FFmpegKit (new) rather than Media3 Transformer + AVFoundation

`arthenica/ffmpeg-kit` was retired in January 2025 and its binaries were removed. Its official continuation, FFmpegKitNext (July 2026), is **source-only**: you build it yourself with Nix or MSYS2, and it ships no pub.dev package. The actively maintained Flutter fork **`ffmpeg_kit_flutter_new`** (sk3llo, verified publisher antonkarpenko.com) ships prebuilt **FFmpeg 8.1.2** for Android, iOS, macOS, Windows and Linux, supports SwiftPM and is updated frequently (2.7.2 / 4.7.2 published 2026-11-17). We use the `_min_gpl` variant: the smallest build that includes x264.

A native Media3 Transformer (Android) plus AVFoundation (iOS) pipeline would avoid the GPL and use hardware codecs, but it means two separate implementations of every feature (xfade transitions, audio mixing, reverse, LUTs, overlays) behind platform channels, and the results would not match exactly across platforms. FFmpeg gives one tested, pure-Dart command builder for both platforms. Hardware encoders are still available through `VideoEncoder.mediacodec` / `VideoEncoder.videotoolbox`. A Media3/AVFoundation backend behind the same `VideoEngine` interface is on the roadmap.

## AI

* `InferenceEngine` abstracts the runtime. `OnnxInferenceEngine` uses **flutter_onnxruntime** 1.9 (updated 2026-10; the older `onnxruntime` package has not been updated since 2024) with CoreML on iOS and XNNPACK on Android, falling back to CPU. Sessions are cached per model.
* `ModelManager` streams downloads from Hugging Face, hashes them with SHA-256 on the fly, writes to `*.part` and renames only on a checksum match. Concurrent requests share one download.
* Pipelines and their tensor contracts (checked against the actual ONNX graphs with onnxruntime before they were written):

| Model | Inputs | Output |
|---|---|---|
| U²-Net-p | `input.1` f32 [1,3,320,320] (ImageNet norm) | `1959` [1,1,320,320] sigmoid, min-max normalised |
| MODNet (int8) | `input` f32 [1,3,H,W], H/W multiples of 32, (x-0.5)/0.5 | `output` [1,1,H,W] alpha 0..1 |
| Real-ESRGAN General x4v3 | `image` f32 [1,3,128,128] 0..1 | `upscaled_image` [1,3,512,512] 0..1 |
| MI-GAN pipeline | `image` u8 [1,3,H,W], `mask` u8 [1,1,H,W] (255 keep, 0 erase) | `result` u8 [1,3,H,W] |
| LaMa (Carve) | `image` f32 [1,3,512,512] 0..1, `mask` f32 [1,1,512,512] (1 erase) | `output` [1,3,512,512] (auto-detects 0..1 vs 0..255) |

* No ML Kit and no Google services. The app has no network traffic apart from model downloads.

## Persistence

Drift (SQLite via `drift_flutter`, using the `sqlite3` 3.x build hooks) keeps the `projects` table: id, name, kind, source path, thumbnail, edit JSON and timestamps. Preferences use `shared_preferences`.

## v1.1 additions

### Presets
* `PresetLibrary` (pure) holds the user's presets and favourites; `PresetLibraryController` persists it in SharedPreferences. Preset files are versioned JSON (`{"format":"lumora.presets","version":1,"presets":[…]}`), validated and range-clamped on import.
* `Preset.apply` / `Preset.remove` are inverse operations for scalar sliders, so switching looks never stacks them, also for user presets.
* `PresetThumbnailCache` downsizes the preview to ≤ 220 px once, then renders `stateFor(preset)` (base edit without the active preset + crop) through a dedicated `PhotoRenderer`, one thumbnail per event-loop turn, only for tiles that are on screen. The cache is invalidated when the photo, base edit or crop changes.

### Finishing (frame, watermark, social sizes)
* `layoutFrame` (pure) computes the canvas and photo rect for every frame style. Preview: `FinishingRenderer.preview` draws on the GPU canvas (blur fill via `ImageFilter.blur`). Export: `applyFrame` composes on the CPU in an isolate (any size, no GPU texture limit) and only the watermark's bounding box is rasterised on the GPU (`TextPainter`, so Arabic shapes correctly) and alpha-blended.
* The editor shows the un-framed image while a tool needs image coordinates (crop, text, brushes, masks, heal, colour picker).

### Healing / clone
* `applyHeal` works on full-resolution pixels in an isolate. Heal searches 24 directions × 4 distances for the source window whose border ring best matches (SSD), copies it, then adds the destination−source difference measured on the mask border, interpolated with inverse-distance weights (a membrane approximation of Poisson blending). Clone copies from a user-chosen offset. Results are stored as a new raster (`rasterPath`) like the AI tools, so undo works.

### Histogram & clipping
* After each render the image is downscaled to 256 px on the GPU and read back for `Histogram.fromRgba`. `clipping.frag` paints blown highlights red and crushed shadows blue as an overlay of the same size as the preview.

### Document scanner
* `detectDocument`: ≤ 360 px proxy → luminance + blur → Otsu (both polarities) → largest 4-connected region → convex hull of its row extents → largest-area quad (corner refinement) → confidence = rectangularity² × size.
* `warpPerspective` solves the homography from the output rectangle to the quad (8×8 Gaussian elimination) and samples bilinearly. `applyScanFilter` divides by an illumination estimate (max-filter + blur on a 96 px copy), which removes shadows and whitens paper; B&W uses a smoothstep threshold on the normalised luminance.
* `buildImagePdf` writes PDF 1.4 with one DCTDecode image XObject per page and a byte-exact xref table.

### Video
* `LookTimeline` (pure): keyframe interpolation, FFmpeg expression generation (`if(lt(T,t1),lerp,…)`), `scaleLook`. Fast export: `split → look → blend=all_expr='A+(B-A)*(k(T))'`. Studio export scales the look per frame. Preview scales the look at the playhead.
* Stabilisation: `vidstabdetect` on the trimmed source (`-ss/-t`) writes a `.trf`, then `vidstabtransform` is inserted right after `trim,setpts` in that clip's chain (before reverse/crop/rotate), followed by a light `unsharp`.
* GIF: the cut is rendered at 480p, then `fps,scale,split → palettegen / paletteuse`.
* All generated command lines were run against a real FFmpeg build while developing (see `test/unit/video_v11_test.dart` for the structure checks and an evaluator for the keyframe expression).
