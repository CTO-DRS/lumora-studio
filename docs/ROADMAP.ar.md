## 1. أين نحن الآن (موجات مغلقة)

الموجة الأولى — **الإصدار 1.3 «الذكي» + تحسينات 1.3.3** ✅ — أوامر مكتوبة بالعربية والإنجليزية تتحول إلى خطة تعديل بخطوة واحدة بدقة 100٪ (1070 أمرًا)، مقترحات ذكية، تحديد بالنقر (MobileSAM متعدد الأقنعة، صندوق، فرشاة تنقيح، حواف ناعمة)، تمويه العمق وإعادة الإضاءة، إزالة الأشخاص، معجم اللهجات (خليجي/مصري/شامي/مغاربي)، مرايا النماذج.

الموجة الأولى ب — **الإصدار 1.4.0 «أسس الاحترافية»** ✅ (هذا الإصدار، 2026-11-25) —
- **الوجوه:** تنقيح البشرة وحدها، إشراق العينين، تبييض الأسنان عبر YuNet + شبكة MediaPipe ذات 478 نقطة (5.1 ميجابايت، ≤ 60 مللي ثانية للوجه).
- **السماء والمشهد:** تجزئة سماء U²-Net بتكميم int8 داخلي (44.2 ميجابايت، ~305 مللي ثانية عند 320²، توافق ≈ 0.93)، تعزيز السماء + استبدالها (4 تدرجات إجرائية)، مصنّف مشاهد MobileNetV2 (3.5 ميجابايت) يقوّي مقترحات الشريط الذكي.
- **أسس الفيديو:** موجة صوتية + كشف إيقاع بتدفق الطاقة ومحاذاة التقسيم على الإيقاع (معالجة إشارة نقية بلا نماذج).
- **القص:** تسوية تلقائية بكاشف أفق Hough (نقي بلا نماذج، ~2 مللي ثانية).
- **بنية احترافية:** خط تكميم int8 داخلي (`tool/quantize_skyseg.py`)، مرايا نماذج على مستضيف المشروع (وسم `models-v1.4`)، سياسة خصوصية (عربي/إنجليزي)، معيار نوايا بـ 1128 أمرًا بدقة 100٪.

## 2. رؤية الموجة الثانية

كل ميزة احترافية ما تزال حكرًا على السحابة في 2026 — معالجة RAW، التسميات التوضيحية التلقائية، إنقاذ الإضاءة الخافتة، التنقيح الاستوديو للوجوه — تُشحن خلف اشتراكات وأرصدة ورفع للملفات. الموجة الثانية تجيب بفكرة واحدة: **اجعل معالج الهاتف نفسه يقوم بالعمل الاحترافي.** محرك LiteRT/NPU الجديد يحوّل كل نموذج قادم إلى استدلال مسرّع عتاديًا وودود للبطارية يحترم وعد «100٪ على الجهاز»؛ وخط أنابيب RAW/DNG يزيل سقف 8-بت بين لومورا والكاميرات الحقيقية؛ وتسميات Whisper تجعل نشر الفيديو العربي/الإنجليزي ممكنًا على متن طائرة؛ وتجزئة الوجه وإنقاذ الإضاءة الخافتة يغلقان آخر فجوتين صادقتين في جدول المنافسة.

الموجة الثانية = **الإصدار 1.5 «الذكاء الاحترافي»** (الهدف: الربع الأول–الثاني 2027)، خمسة مسارات عمل فوق أساس تشغيل واحد مشترك.

## 3. مسارات عمل الموجة الثانية

### مس 1 · محرك LiteRT/NPU 🚧 *يبدأ الآن (أول بند في الموجة)*

| | |
|---|---|
| **الهدف** | كل نموذج يعمل بأسرع محرك يوفره الجهاز — NPU حيث يوجد، ثم GPU، ثم CPU كحد أدنى — دون أي تغيير في السلوك للمستخدم ودون أي انحدار في الانهيارات. |
| **النطاق** | تجريد موحّد `InferenceEngine` خلف محرك ONNX الحالي: `lite_rt_engine.dart` (عبر tflite_flutter) بسلسلة احتياط **مفوّض NPU (QNN / NNAPI حسب المعالج)** ← **مفوّض GPU** ← **XNNPACK CPU**؛ قائمة سماح لكل معالج (SoC) وحماية انهيار مع احتياط تلقائي (أي مفوّض ينهار مرة يُحظر للجلسة)؛ اختيار المحرك والمفوّض لكل نموذج في السجل؛ النماذج قد تُشحن بصيغتين (`.onnx` لـ ONNX/CPU و `.tflite` لـ LiteRT) بعقد واحد؛ قياس الزمن والذاكرة يبقى محليًا (الإعدادات › التشخيص) وقابل للتصدير من المستخدم. |
| **النماذج/التقنية** | `tflite_flutter` (LiteRT)، مفوّض GPU، مفوّضات NNAPI/QNN، قائمة سماح (Snapdragon 8 مع QNN، Tensor، مسار Core ML عبر ANE على iOS 🧪). |
| **الأهداف** | ترميز MobileSAM أسرع ≥ 2× على أجهزة NPU مقابل CPU ONNX؛ مصنّف المشاهد ≤ 5 مللي ثانية على GPU؛ السماء 320² ≤ 150 مللي ثانية على NPU؛ لا انحدار في الانهيارات على المزرعة (خلو من الانهيار ≥ 99.8٪)؛ الأجهزة CPU-فقط تبقى بسلوك اليوم حرفيًا. |
| **القبول** | `flutter analyze` نظيف؛ اختبارات وحدة لاختيار المفوّض والاحتياط والحظر؛ مصفوفة مزرعة (≥ 12 جهازًا) خضراء مع إثبات الاحتياط التلقائي على مفوّض معطوب عمدًا؛ جدول قياس (محرك × مفوّض × نموذج) يُنشر مع كل إصدار. |

### مس 2 · خط أنابيب RAW/DNG ذي 16-بت 🔜

| | |
|---|---|
| **الهدف** | فتح ملفات الكاميرات الحقيقية (DNG/RAW) بلا سقف JPEG ذي 8-بت: فك 16-بت ← خط داخلي 16-بت ← توطين نغمي عند التصدير. |
| **النطاق** | فك ترميز DNG/TIFF (JPEG بلا فقد + deflate + غير مضغوط)، مسار سريع للمعاينة المصغرة المضمّنة للعرض الفوري، مخازن داخلية float 16-بت من طرف لطرف (المظللات + الأقنعة + LUTs)، استرداد الإبرازات من البيانات الخطية، توطين نغمي محايد الكاميرا إلى sRGB/Display-P3 مع تدرج قابل للضبط للظلال والإبرازات، تصدير TIFF 16-بت / JPEG / HEIC، معالجة بلاطات للملفات ≥ 24 ميجابكسل. |
| **النماذج/التقنية** | مفكك DNG بلغة Dart/Rust 🧪 (دلالات من فئة libraw، أجزاء MIT/Apache فقط)، خط GLSL الحالي ممتد إلى RGBA16F. |
| **الأهداف** | فتح DNG بـ 24 ميجابكسل ≤ 2 ثانية (المعاينة أولًا < 300 مللي ثانية)؛ ذاكرة ذروة ≤ 900 ميجابايت لـ 24 ميجابكسل 16-بت؛ لا انحدار للصور 8-بت (المظللات نفسها، مسار شيفرة واحد). |
| **القبول** | مفكك مختبر بالعشوائية على ملفات DNG تالفة (بلا انهيار)؛ دقة لونية مقابل فك مرجعي (ΔE ≤ 2 على مجموعة معايرة)؛ اختبارات ذهبية لمسار المظللات 16-بت. |

### مس 3 · تسميات Whisper التلقائية (عربي/إنجليزي، دون شبكة) 🔜

| | |
|---|---|
| **الهدف** | تسميات توضيحية بضغطة واحدة للفيديو — عربي وإنجليزي — تعمل حصريًا على الجهاز، بنمط أداة النص، تُصدَّر محفورة داخل الفيديو أو كملف SRT/VTT جانبي. |

| **النماذج/التقنية** | Whisper tiny (~39 مليون معامل؛ int8 ≈ 40 ميجابايت) أولًا، base اختياري؛ أوزان MIT/Apache فقط؛ عقد سجل النماذج والمرايا كالمعتاد. |
| **الأهداف** | ≥ 1× الزمن الحقيقي على هاتف المرجع (tiny int8)؛ ذاكرة ≤ 2 جيجابايت؛ معدل خطأ الكلمات العربية على مجموعة لهجات محتجزة ≤ 18٪ (tiny) / ≤ 12٪ (base)؛ التسميات لا تحجب التحرير أبدًا (مهمة خلفية قابلة للإلغاء). |
| **القبول** | معيار وحدات على عينات تركيبية وحقيقية؛ اختبارات ودجات لواجهة ترجمة الطريقة الزمنية؛ تشكيل عربي سليم (بلا وصلات مكسورة) بختبارات ذهبية. |

### مس 4 · تجزئة الوجه (تحليل الوجه) 🔜

| | |
|---|---|
| **الهدف** | الانتقال من أقنعة مبنية على المعالم إلى تحليل وجه حقيقي لكل بكسل: بشرة، حواجب، عينان (ي/م)، نظارات، شفاه، أسنان، شعر، خلفية — لتمكين تنقيح استوديو لا يتسرب أبدًا. |
| **النطاق** | نموذج تحليل وجه (BiSeNet-class بأقنعة CelebAMask-HQ ذات 19 فئة، أوزان برخص نظيفة فقط 🧪 — الأوزان غير التجارية مرفوضة بالسياسة)، يعمل لكل وجه مكتشف (يعيد استخدام YuNet من 1.4)، معرّفات الفئات ← أقنعة دلالية، يستبدل أقنعة البشرة/العينين/الأسنان المبنية على المعالم حيث يكون التحليل واثقًا (هجين: المعالم تبوّب، التحليل يصقل)، أدوات جديدة: إبراز الحواجب، تقليل انعكاس النظارات، لون الشفاه (HSL عبر قناع الشفاه)، صبغ الشعر، منزلقات قوة لكل فئة، كلها تعديلات محلية قابلة للتحرير. |
| **النماذج/التقنية** | تحليل وجه int8 (ميزانية ≤ 10 ميجابايت، استدلال 512²)، خط الوجه الحالي مضيفًا. |
| **الأهداف** | ≤ 120 مللي ثانية للوجه عند 512² على هاتف المرجع (≤ 400 مللي ثانية على CPU)؛ توافق الفئات على صور محتجزة: بشرة ≥ 0.85، شفاه ≥ 0.8، شعر ≥ 0.8؛ الأقنعة لا تكتب خارج منطقة تكبير قص الوجه أبدًا. |
| **القبول** | مجموعة قياس بأقنعة بكسلية (جدول IoU منشور)؛ أوامر ذكية جديدة عربي/إنجليزي («صبغ الشعر»، «أحمر الشفاه»، "tint my hair"، "lip colour"…) تضاف لمعيار النوايا بدقة 100٪؛ اختبارات وحدة للبوابة الهجينة. |

| | |
|---|---|
| **الهدف** | رفع لقطات ليلية داكنة ومشوشة إلى جودة قابلة للنشر — إزالة ضجيج، سطوع، ضجيج لوني — كلها على الجهاز وقابلة للتحرير. |

## 6. بوابات الجودة (مبادئ ثابتة، سقف أعلى)

- معيار النوايا ينمو مع كل مسار (أوامر التسميات، الشعر والشفاه، أوامر الليل) — **دقة ≥ 100٪** قبل الإصدار، عربي وإنجليزي منفصلين.
- كل نموذج جديد: رابط مثبت + SHA-256، بوابة رخصة (لا أوزان غير تجارية)، زمن وذاكرة مقيسان يُنشران في `docs/SMART_EDIT.md`، مرآة على `models-v1.5`.
- مصفوفة مزرعة ≥ 12 جهازًا (3 فئات × نظامان × مورّدان)، خلو من الانهيار ≥ 99.8٪، تتبع حراري لجلسة 10 دقائق.
- اختبار عشوائي: مفكك DNG، كتبة SRT/VTT، JSON الترجمة؛ اختبارات ذهبية لمظللات 16-بت وتنسيق الترجمة.
